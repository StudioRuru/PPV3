# Dynamic Island Live Activity — Plan 21 (sub-project 9, P3)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development (owner's choice). Web steps are TDD (write the named tests, watch them fail, implement, pass). Swift steps are verified by `xcodebuild` (no Swift test target in this repo) plus the owner's on-device check.

**Goal:** When the Studio app is in the background, Miyabi lives in the real Dynamic Island as a Live Activity — compact (her mood bust + current tab), minimal (bust), expanded (Summon / Hide buttons and Open Studio / Open Chat) — and those buttons drive the web app.

**Architecture:** The web app reports a small activity state over the existing `webkit.messageHandlers.studio` bridge; the native shell (`ios/App`) keeps one ActivityKit Live Activity in sync and writes Miyabi's downscaled bust to the app-group container; a new WidgetKit extension (`ios/Widgets`) renders the island; buttons are iOS 17 `LiveActivityIntent`s (Summon/Hide, queued in the app group and delivered to the page via `window.studioIntent`) and `naistudio://tab/<tab>` links (Open Studio/Chat).

**Tech stack:** Swift 5, ActivityKit, WidgetKit, AppIntents (iOS 17), xcodegen; Next.js/React for the web half; node:test via tsx.

**Spec:** `docs/superpowers/specs/2026-10-15-mascot-stage-nav-chat-design.md` §5. P1/P2 shipped in plans 19–20.

- Build check: `cd ios && xcodegen generate --quiet && xcodebuild -project NAIStudio.xcodeproj -scheme NAIStudio -configuration Release -destination generic/platform=iOS -derivedDataPath build -allowProvisioningUpdates -quiet build`. **Never run `ios/build.sh` or `devicectl`** — installing on the owner's phone is the controller's call after asking.
- iOS rules this design must respect: an app's own Live Activity isn't shown in its island while the app is in the foreground; `Activity.request` only works while the app is in the foreground; activities end after ~8 h; widget images must be small (downscale to ≤ 120 px, PNG in the app-group container).
- Live Activity lifecycle: request once while active (first foreground with a known state); update on state changes; if it has ended (8 h, user swiped it away), request again on the next foreground. Setting toggle: web setting `mascot.island.activity` (default on) → off ends it and stops requests.
- Bridge (web → native): `postMessage({ activity: { tab: Tab, tabLabel: string, expression: Expression, hidden: boolean, bust: string | null, on: boolean } })` — `bust` is a same-origin path; native fetches it with the WKWebView cookies (as `save` does today), only if same-origin. Throttled to ≤ 1 message / 2 s and only when something changed.
- Native → web: `window.studioIntent?.(intent)` with `intent = { tab: Tab } | { mascot: "hide" | "summon" }`; the web validates it (`parseIntent`) and ignores anything else. Pending intents (app was suspended) are delivered on the next `didFinish`/`becameActive`, oldest first, then cleared.
- URL scheme: `naistudio://tab/<studio|roll|closet|chat|rp>`; anything else ignored (`naistudio://import` keeps its current meaning).
- No secrets or auth in the app group or activity state; activity content = tab label, expression name, hidden flag, image file.

## Review focus
1. Lifecycle never errors visibly or leaks: no `Activity.request` from background; ended/dismissed activities are re-requested only in foreground; turning the setting off ends it; no duplicate activities after relaunches (reuse `Activity<…>.activities.first`).
2. Untrusted input on both bridges: the page's activity message (types, lengths, same-origin bust path) and the intent/URL path (only whitelisted tabs/actions reach JS; JS is called with `callAsyncJavaScript` arguments, never string-built).
3. Pending intents survive a suspended/killed app (app group queue) and are applied exactly once, in order.
4. The web half is inert outside the iOS shell (no `webkit.messageHandlers` → no posts, no errors) and adds no work per frame (throttled, change-only).
5. Widget extension stays within limits: tiny images, no network in the widget, no app-only APIs in extension code.
